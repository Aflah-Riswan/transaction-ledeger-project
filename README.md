# Transaction Ledger API

A backend REST API for a transaction ledger system built with Node.js, TypeScript, Express, and MongoDB (Mongoose). It allows users to create accounts, perform credit and debit transactions, retrieve account balances, and view paginated transaction history with complete data integrity and overdraft protection.

## Features & Requirements

- **Create Account**:
  - Unique ID generated by MongoDB.
  - Account name is required and trimmed.
  - Initial balance is strictly `0` (client cannot set initial balance).
  - System-generated creation timestamp (`created_at`).
- **Add Transaction**:
  - Supports `credit` (increases balance) and `debit` (decreases balance).
  - Rejects debits exceeding current balance (no negative balances allowed).
  - Enforces unique `reference_id` per account (compound unique index prevents duplicates).
  - Same `reference_id` is permitted across different accounts.
  - Transaction immutability: once created, transactions cannot be updated or deleted.
- **Get Account Balance**:
  - Fetches current balance for existing account.
  - Returns `404 Not Found` if account does not exist.
  - Validates account ID format.
- **Get Transaction History**:
  - Filter by transaction type: `credit`, `debit`, or all.
  - Pagination with `page`, `limit`, `total_records`, `total_pages`.
  - Ordered latest-first by `created_at`.
- **Validation & Error Handling**:
  - Plain TypeScript validations without external validation libraries (no Zod/Joi).
  - Clear, human-readable error messages and proper HTTP status codes (`200`, `201`, `400`, `404`, `409`, `500`).

### 2. Create Account
`POST /api/accounts`

```json

}
```

### 3. Get Account Balance
`GET /api/accounts/:accountId/balance`

**Response (`200 OK`):**
```json
{
  "success": true,
  "data": {
    "account_id": "6720f188365ef5cb2e1b1234",
    "balance": 15000
  }
}
```

---

### 4. Add Transaction (Credit / Debit)
`POST /api/accounts/:accountId/transactions`

**Request Body (Credit):**
```json
{
  "type": "credit",
  "amount": 5000,
  "reference_id": "ref-salary-01",
  "description": "Salary payment"
}
```

**Request Body (Debit):**
```json
{
  "type": "debit",
  "amount": 1200,
  "reference_id": "ref-groceries-01",
  "description": "Weekly grocery purchase"
}
```

**Response (`201 Created`):**
```json
{
  "success": true,
  "data": {
    "id": "6720f1a0365ef5cb2e1b5678",
    "account_id": "6720f188365ef5cb2e1b1234",
    "type": "credit",
    "amount": 5000,
    "description": "Salary payment",
    "reference_id": "ref-salary-01",
    "created_at": "2026-10-29T08:31:00.000Z",
    "new_balance": 5000
  }
}
```

---

### 5. Get Transaction History
`GET /api/accounts/:accountId/transactions?type=credit&page=1&limit=10`

**Query Parameters:**
- `type` *(optional)*: `credit` or `debit`. (Omit to retrieve all transactions).
- `page` *(optional, default: 1)*: Page number.
- `limit` *(optional, default: 10, max: 100)*: Items per page.

**Response (`200 OK`):**
```json
{
  "success": true,
  "data": {
    "transactions": [
      {
        "id": "6720f1a0365ef5cb2e1b5678",
        "account_id": "6720f188365ef5cb2e1b1234",
        "type": "credit",
        "amount": 5000,
        "description": "Salary payment",
        "reference_id": "ref-salary-01",
        "created_at": "2026-10-29T08:31:00.000Z"
      }
    ],
    "current_page": 1,
    "page_size": 10,
    "total_records": 1,
    "total_pages": 1
  }
}
```

## Data Integrity & Concurrency

1. **Atomic Balance Updates & Overdraft Protection**:
   Debits are conditionally updated in MongoDB with `{ balance: { $gte: amount } }`. If the account has insufficient balance or a concurrent request drops the balance, the update returns `null` and the transaction is safely rejected with `Insufficient balance to complete this debit.`.
2. **Duplicate Protection**:
   The unique compound index `{ accountId: 1, referenceId: 1 }` guarantees that no two transactions with the same `reference_id` can be created for the same account.
3. **Transaction Immutability**:
   Transaction records cannot be edited or deleted through the API.
4. **Compensation on Error**:
   If creating the transaction record fails, any applied balance update is immediately rolled back.

## Error Handling

| Situation | HTTP Status | Message |
|---|:---:|---|
| Missing account name | 400 | `Account name is required.` |
| Invalid account ID format | 400 | `Invalid account ID format.` |
| Account not found | 404 | `Account not found.` |
| Invalid transaction type | 400 | `Transaction type must be credit or debit.` |
| Invalid amount | 400 | `Amount must be greater than zero.` |
| Duplicate transaction reference | 409 | `A transaction with this reference ID already exists for this account.` |
| Insufficient balance | 400 | `Insufficient balance to complete this debit.` |
| Invalid pagination parameters | 400 | `Page and limit must be valid positive integers.` |
| Unexpected server error | 500 | `An unexpected error occurred. Please try again later.` |
